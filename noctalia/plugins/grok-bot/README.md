# Grok Bot for Noctalia

本机 Noctalia/niri 插件，包含动态角色小队、按需展开聊天、本地消息桥接与真实运行状态。

## 使用

- 顶栏左键展开小队；点击头像展开该 BOT 聊天，再点同一头像或“收起聊天”隐藏聊天。
- 右键打开 Grok Bot。应用未启动时，插件通过桥接启动应用。
- 工作或等待处理的成员会从顶栏主 BOT 后探出，最多十个，更多显示 +N。
- 聊天显示最近 60 条本地消息。每个 BOT 独立保留内存草稿。
- 桥接连接后，在输入框输入并点击“发送”，消息交给应用现有 sendJournal 处理。提示“已提交应用发送队列”不代表服务器已确认或 BOT 已回复；失败保留草稿，不自动重发。

## 桥接启动

**默认跟随插件后台服务自动启动**，无需手动打开第二个启动器。已有桥接时只检查，不重复启动或抢焦点。
插件设置中的“插件启动时自动启动本地桥接”可关闭此行为。服务按启动事件拉起一次，不会每秒把用户主动退出的应用重新打开。
普通的 **Grok Bot** 启动入口也已在用户目录覆盖为桥接入口，保留原有 grokbot/sand 链接处理；系统原始 desktop 文件不改。
桥接启动过程使用当前用户的进程锁防止重复创建。没有设置独立开机服务或修改应用包。

桥接通过 Electron 的 `--remote-debugging-pipe` 连接 renderer；没有 TCP 调试端口。
对插件仅开放当前用户可访问的 Unix socket：`~/.local/state/noctalia-grok-bridge/bridge.sock`（目录 0700，socket 0600）。
接口仅提供 health、status、send；发送校验成员、消息、请求 ID，并在运行期间去重。调用应用内部客户端，不读取登录凭据。
应用升级可能改变内部接口。桥接失效时禁用发送，保留草稿。

## 验证情况

- 实际进程管道连通，读到完整八个成员的 isRunning / isComposingMessage。
- 插件已采用新鲜的运行时状态；桥接不可用时回退本地文件与短消息推断。
- 空消息通过实际 socket 被拒绝，没有调用发送逻辑。
- 42 项插件逻辑测试通过，插件 lint 无错误、无警告。
- **尚未代用户发送真实聊天内容，因此首次实际发送、服务器受理和回复回显仍需用户消息验证。**

## 外观与动画

支持 24 种自行绘制的近似轮廓及 11 种基础颜色、常见别名和十六进制颜色。未支持的形状回退 blob。
独立眼睛动画目标约 30fps，成员依次出现即开始播放。聊天区域在同一面板内进行 260ms 展开/收起过渡。

## 位置和移除

插件：`~/.config/noctalia/plugins/grok-bot/`；Noctalia 配置：`~/.local/state/noctalia/settings.toml`。
桥接状态：`~/.local/state/noctalia-grok-bridge/`；组件健康记录：`~/.local/state/noctalia/plugins/data/local/grok-bot/`。
移除时先退出 Grok Bot，再禁用并删除插件、桥接状态目录及用户覆盖的 `~/.local/share/applications/grok-bot.desktop`（删除覆盖后恢复系统默认启动入口）；原应用不受安装文件修改。

本插件非 xAI 或 Anysphere 官方产品。

顶栏左键使用 Noctalia 原生 togglePanel 直接打开/关闭小队，不再经过子进程 IPC 转发。

输入快捷键：Enter 发送，Shift+Enter 换行；键盘与按钮共用提交处理、防重复点击和桥接连接检查。

透明空白点击修复：聊天收起或展开途中，预留窗口中未显示内容的区域作为关闭背景处理。点击该区域会关闭面板，与点击面板外一致，不影响顶部成员或聊天内容的正常交互。

成员容量：顶栏可露出最多 10 个工作/等待成员（主 BOT 另计）；面板每页最多 32 个成员，每行 8 个，最多四行，每行独立居中；超过 32 个可翻页。紧凑高度按行数增长，聊天跟随实际网格下方展开，透明预留区域保留点击关闭行为。
